osu!mania 4K 谱面播放器（离线单文件版）
================================================================

一、这是什么
----------------------------------------------------------------
一个用 Rust + egui/rosu-renderer 写的 osu!mania 谱面播放器。
- 直接读取 .osz 谱面包（ZIP），解压出 .osu / 音频 / 背景图后播放；
- 可导入多个谱面包并在列表中选曲、选难度；
- 4K 键位为 D F J K，判定窗口遵循 osu! 的 ScoreV1 口径，支持长条（LN）；
- 不计算血量、不允许失败（按需求），只记录分数 / 准确率 / 连击 / 判定；
- 最终产物是一个 .exe，无需安装，无需 Rust 或其他开发工具，运行时不需要网络。

产物：target\release\osu4k-player.exe（约 7.9 MB，单文件，静态 CRT）。
谱面 .osz 不打包进 exe，运行时通过文件对话框（或拖放）加载。
**只需这一个 exe 就能运行**：字体、依赖库、渲染器全部编进 exe，不需要任何
随附 DLL、assets 目录或安装步骤；第一次运行最多会在 exe 同目录自动生成
osu4k_player.ini（配置，可删）。

环境：Windows 10 x64（使用 MSVC 工具链构建；使用静态 CRT，见第九节）。
渲染使用 OpenGL（egui_glow），需要显卡驱动支持 OpenGL 2.0+；普通装有显卡
驱动的 Win10 都满足，纯虚拟机/无显卡驱动环境请看第十三节。

便携包：构建出 target\release\osu4k-player.exe 后，把它与本说明、
THIRD_PARTY.md、assets\OFL-NotoSansSC.txt 放进同一个文件夹即可整体拷贝使用
（发布版另提供 osu4k-player-portable.zip，不在本仓库中）。


二、运行
----------------------------------------------------------------
1. 双击 osu4k-player.exe。
2. 第一次运行点击右上角「导入 .osz」，在弹出的文件对话框里选择 .osz 文件；
   也可以直接把 .osz 文件拖进窗口。
3. 左侧是谱面列表，点击一个谱面包，右侧列出它的 osu!mania 难度
   （显示键数、OD、音符数）。选中难度后点「开始游玩」，或双击难度直接开始。
4. 导入过的 .osz 路径会记录在 osu4k_player.ini 里，下次启动自动出现在列表中。
   文件被移动/删除的条目会在启动时自动移除；「移出列表」只移除记录，不删除文件。

便携性：
  把 osu4k-player.exe 单独复制到任意目录（包括带空格、中文的路径）即可运行；
  程序只会在 exe 同目录写 osu4k_player.ini（若该目录不可写则写到
  %APPDATA%\osu4k-player\），解压缓存写在 %TEMP%\osu4k-player\。
  不需要网络、不写注册表、不安装服务。


三、操作
----------------------------------------------------------------
游玩：
  D F J K           4K 键位
  Esc               暂停 / 继续（暂停时音频停止、画面冻结，并显示半透明覆盖层）
  暂停界面按钮      继续 / 重试 / 返回选曲
  结算界面按钮      重试 / 返回选曲（Esc 也可返回）

键位映射（谱面键数取自 [Difficulty] CircleSize）：
  4K  D F J K
  5K  D F 空格 J K
  6K  S D F J K L
  7K  S D F 空格 J K L
  8K  A S D F J K L ;
  其它键数按上述顺序尽量映射（4K 为主）。

设置（主界面底部「设置」，默认展开，可折叠）：
  下落时间    音符从屏幕顶端到判定线所需毫秒数（越小越快），120–2600 ms
  偏移        整体时间偏移，-300–300 ms，正值让画面/判定整体后移
  音量        0–120 %
  自定义 OD   勾选后用滑条覆盖谱面 OD（0–10，步进 0.1），判定窗口按覆盖后的 OD 计算
  打击音效    使用谱面包内的 *-hitnormal 音效（若存在）
  自动演示    自动以 300 判定播放（可用于预览或验证）
  过快/过慢提示条  在判定线下方显示击打误差条：
              左=快/早，右=慢/晚，竖线为该次击打（按判定上色），
              竖虚线为 300/100 窗口边界，三角为最近 20 次平均值
  皮肤        显示当前皮肤名；「导入皮肤文件夹」加载 osu!mania 皮肤目录，
              「清除皮肤」回到内置样式（见第八节）
  保存设置    写入 osu4k_player.ini（导入/移出谱面时也会自动保存）

谱面列表中的星数：
  每个谱面包右侧显示该包内最高难度星级，难度列表显示每张难度的星级，
  例如 ★4.36。星数由 rosu-pp 3.1.0（osu! 官方难度算法，mania 4K）在导入
  / 启动扫描时计算，精确到小数点后 2 位；显示为“★—”表示该难度无法计算。


四、判定规则（ScoreV1 口径）
----------------------------------------------------------------
OD 从 [Difficulty] OverallDifficulty 读取，并钳制到 0–10；若在设置里启用了
“自定义 OD”，则改用设置值（同样钳制到 0–10）。判定窗口：

  300   ±(64  − 3 × OD) ms
  100   ±(97  − 3 × OD) ms
  50    ±(127 − 3 × OD) ms
  超过 50 窗口（或漏按）记 Miss

- 按键时在该列找最早一个尚未判定的音符，若按键时刻落在它的 50 窗口内则判定，
  否则不影响该音符（避免“抢拍”消耗音符）。
- 音符的 50 窗口结束后仍未命中 → 自动 Miss，连击中断。
- 连击：300/100/50 都增加连击，Miss 清零；结算显示最大连击。
- 准确率 = (300×n300 + 100×n100 + 50×n50) / (300×总判定数)，总判定数包含 LN 尾判。
- 分数按 1,000,000 归一化（完美全 300 = 1,000,000）。
- 评级：全部 300 为 SS，准确率 ≥95% 为 S，≥90% A，≥80% B，≥70% C，其余 D；
  Miss 为 0 时显示“全连”。

长条（LN）：
- 头部只判定一次（按上面的 300/100/50 窗口）；
- 按住到尾部 → 尾判 300；
- 提前松开 → 按“松开时刻与尾部时刻的偏差”判定：
    偏差 ≤ 100 窗口 → 100
    偏差 ≤ 50 窗口  → 50
    否则 → Miss
- 头判 Miss 时该 LN 只记一次 Miss（不再单独计尾判）。
- 若松开事件因窗口失焦/暂停丢失，会与真实按键状态对账，避免白嫖长条。
- 暂停时按住的长条不会中断；从暂停恢复后如果按键已经松开，会按恢复时刻补判。


五、时间与音画同步（重要：两个上游 API 限制与处理方式）
----------------------------------------------------------------
1) rodio 0.17 没有 Sink::get_pos()
   需求里要求“以 rodio 的 Sink::get_pos() 为权威时钟”，但经核对源码，
   rodio 0.17.3 的 Sink 只有 append/play/pause/stop/volume/speed/len 等，
   并没有 get_pos()（该 API 是更新版本才加入的）。为此本项目在音频源内部
   自行实现了等价机制：

     Decoder -> ClockSource（每个被设备取走的采样 +1） -> Sink -> 混音器

   这和新版 rodio 的 get_pos 是同一原理：位置来自“真正被输出设备拉取的
   采样数”，而不是墙上时钟。暂停 Sink 时源不再被拉取，计数自然冻结，因此
   暂停/继续天然对齐；播放位置 = 采样数 / (声道数 × 采样率)。

2) rosu-renderer 没有外部时钟入口
   rosu-renderer 1.2.3 的 Player 自己持有 std::time::Instant，
   只有 set_current_time() 会重设它的时间锚点，没有“每帧传入时间”的 API，
   而且它的音符映射会把音符提前一个 scroll_time 到达判定线。直接使用无法
   保证判定与画面同源。解决方案：把 rosu-renderer 1.2.3（MIT）vendor 到
   third_party/rosu-renderer，并做了最小改动：

     - 新增 Player::render_at_time(ui, time_ms, position, pressed)，
       时钟由调用方（音频时钟）传入；
     - 修正音符映射：head_y = 判定线 − (start − now) × 像素/毫秒，
       音符在自身时间恰好到达判定线；
     - 播放区裁剪、判定线/列底色/按压高亮可配置、LN 主体按判定线裁剪；
     - 去掉未使用的 eframe/egui_extras/image 依赖，避免把 rav1e/wgpu 等
       体积与编译时间拖进来。
   详见 third_party/rosu-renderer/PATCHES.md。

3) 实际的数据流
   音频采样计数 →（毫秒）→ 相位锁定的小幅平滑（以音频位置为准，偏差过大时
   直接吸附）→ 同一次时间值同时用于“绘制谱面”和“判定按键”
   因此画面、判定、音乐三者由同一个时钟驱动；暂停时三者一起冻结/恢复。


六、音频
----------------------------------------------------------------
- 使用 rodio 0.17（Windows 上经 WASAPI 输出），纯 Rust 解码：
  mp3（symphonia）、ogg/vorbis（lewton）、wav（hound）、flac（claxon）。
- 不引入任何需要手动放置 DLL 或额外安装运行库的音频后端。
- 运行时可播放谱面包内的打击音效（normal/soft/drum-hitnormal）。
- 没有可用音频设备时不会崩溃：自动退回静音 + 墙钟模式，并在画面左下角提示。


七、字体（内嵌，不依赖系统字体）
----------------------------------------------------------------
egui 自带字体的子集几乎不含中文，干净 Win10 上会显示“豆腐块”。本项目：
- 内置 Noto Sans SC（SIL OFL 1.1）的子集 assets/NotoSansSC-subset.otf，
  通过 include_bytes! 编进 exe，启动时注册为比例字体（并作为等宽字体回退）；
- 子集覆盖：ASCII/拉丁、标点/箭头/符号、假名、全角、GB2312 全部汉字、
  JIS X 0208 汉字 —— 常见的简中/日文曲名、难度名都能显示；
- 生成脚本：tools/make_font_subset.py（开发机用 Python + fonttools，
  目标机不需要）；
- 为什么没有直接用 egui_zhcn_fonts：该 crate 是从系统字体目录（如
  C:\Windows\Fonts）加载中文字体，正是需求里“运行时从系统路径碰运气”的做法，
  在缺少字体/被精简的机器上不可靠。内嵌子集体积约 2.5 MB，换来确定性。


八、渲染
----------------------------------------------------------------
- 谱面播放区（列、判定线、普通音符、长条、按压特效）由 vendored 的
  rosu-renderer 绘制；
- 未加载皮肤时，按下按键会在轨道内出现一道**从判定线向上延伸、透明度
  渐隐的蓝色光柱**，并轻微溢出到轨道两侧（不再是均匀半透明长条）；
- 背景图（来自 .osz 的 [Events] 背景文件）、HUD（曲名/难度/OD/分数/准确率/
  判定统计）、连击、判定文字、按键提示、进度条、暂停与结算覆盖层由本程序
  用 egui 自绘。

八·一 皮肤（osu!mania 4K）
----------------------------------------------------------------
在「设置」里点「导入皮肤文件夹」，选择解压好的皮肤目录（目录里有
skin.ini 和 mania-* 图片；.osk 压缩包请先解压）。加载后：
- 音符/长条：mania-note1/2/3…/S 及同名 H/L/T（头/身/尾）图片，4K 按 osu!
  的镜像规则 1,2,2,1 取图，优先使用 @2x 版本；
- 打击特效：mania-hit300/300g/100/50/0 在判定线处播放（随打击散开、
  淡出）；皮肤没有对应图片时退回内置圆环；
- 按键光效：lightingN-<列>（普通键）与 lightingL-<列>（长条按住），
  没有时使用上面的内置渐变光柱；
- 判定线：mania-stage-hint；列颜色：skin.ini [Mania] 的 Colour1..N，
  列分隔线颜色：ColourColumnLine；
- 皮肤缺少的元素会自动回退到内置样式，缺图也能玩；
- 设置项会记住皮肤路径（osu4k_player.ini 的 skin=），「清除皮肤」恢复内置样式。
暂不支持：mania-key*（键帽用内置按键提示）、mania-stage-left/right/bottom、
combo/score 数字贴图、动画帧序列（只取第一张/无 @2x 时取 1x）。


九、构建与离线验证
----------------------------------------------------------------
工具链：Rust 1.88.0（MSVC），Windows x64。

项目包含：
- Cargo.lock（锁定全部依赖版本与校验和，必须保留）；
- .cargo/config.toml（开发机依赖源镜像 + 静态 CRT 开关）；
- 全部依赖已在开发机上完成一次拉取（本地 cargo 缓存），之后一律离线构建。

离线构建/测试（已在本机反复验证通过）：

    cargo build --release --offline
    cargo test --offline

--offline 会让任何网络访问直接失败，因此该命令通过即可证明：构建过程不需要
联网、不会触发构建脚本的隐式下载（本项目依赖中没有需要联网的 build.rs 行为）。
产物为 target\release\osu4k-player.exe，单文件，无需附带任何 DLL 或数据文件。

说明：开发机到 static.crates.io 的连接不稳定，首次拉取依赖时曾临时使用
rsproxy 镜像；本仓库的 .cargo/config.toml **不包含**镜像配置（避免强制所有
使用者走第三方源），需要时请自行添加 [source] 段。首次拉取后
cargo build --release --offline 已通过，因此未再使用 cargo vendor（本机 vendor
需要为所有平台重新解析索引，网络不稳定导致中断）。如果要在另一台机器上复现
离线构建，推荐两种方式：
  1) 在能联网的机器上执行：
         cargo fetch
         cargo vendor vendor
     然后把 vendor/ 连同工程一起拷走，并把 .cargo/config.toml 改成：
         [source.crates-io]
         replace-with = "vendored-sources"
         [source.vendored-sources]
         directory = "vendor"
     之后在任何机器上 cargo build --release --offline 即可（不依赖全局缓存）。
  2) 或者直接在目标机复制开发机的 %USERPROFILE%\.cargo 缓存（体积较大）。

关于静态 CRT：
.cargo/config.toml 中设置了
    [target.x86_64-pc-windows-msvc]
    rustflags = ["-C", "target-feature=+crt-static"]
因此 exe 静态链接 C 运行库，不依赖 vcruntime140.dll / msvcp140.dll。
若你删掉这段并重新构建，产物会改为动态 CRT（此时请看下一节）。


十、VC++ 运行库（可能缺失 vcruntime140.dll）
----------------------------------------------------------------
默认构建（本仓库当前产物）使用静态 CRT，正常情况下不需要 VC++ 运行库。
但如果你自行用默认的 MSVC 动态 CRT 重新构建，或换用别的工具链产物，干净
Win10 上有可能缺少 vcruntime140.dll / vcruntime140_1.dll / msvcp140.dll，
表现为启动即报“缺少 VCRUNTIME140.dll”或 0xc000007b。

离线安装指引（目标机无需联网即可完成）：
1. 在有网的机器上下载微软官方离线安装包（约 25 MB）：
     https://aka.ms/vs/17/release/vc_redist.x64.exe
   （即 Microsoft Visual C++ 2015-2022 Redistributable x64）
2. 用 U 盘/内网把 vc_redist.x64.exe 拷到目标机。
3. 双击安装（需要管理员权限，安装过程不联网）；或命令行静默安装：
     vc_redist.x64.exe /install /quiet /norestart
4. 重新启动播放器。
多数已激活的 Win10 已自带该运行库，通常可以忽略本节。
不建议手工复制 DLL 到 exe 旁边（版本不匹配可能崩溃）。


十一、缓存与配置
----------------------------------------------------------------
- .osz 解压位置：%TEMP%\osu4k-player\cache\<哈希>\ ；程序启动时会清空该目录，
  运行期间按需解压。删除它不会影响任何源文件。
- 配置：优先写在 exe 同目录的 osu4k_player.ini（便携）；若该目录不可写
  （例如放在 Program Files），则写到 %APPDATA%\osu4k-player\osu4k_player.ini。
- 程序不上传数据、不写注册表、不需要网络。


十二、自检（可选）
----------------------------------------------------------------
    osu4k-player.exe --selftest "谱面1.osz" "谱面2.osz"

会用无窗口模式检查：.osz 解压、.osu 解析、OD 判定窗口、长条头/尾判定、
自动播放整张谱面是否全部 300、音频文件是否能完整解码。结果打印到标准输出
并写入 selftest.log，全部通过时退出码为 0。

启动参数（用于演示/测试，可省略）：
    --auto <文件.osz>    启动后自动导入并开始指定的谱面
    --auto-diff <序号>   配合 --auto，选择难度序号（从 0 开始）
    --autoplay           自动演示


十三、已知限制
----------------------------------------------------------------
- 只支持 osu!mania（4K 为主，其它键数按第三节映射）；不支持 osu!/taiko/catch。
- 不做血量/失败判定（按需求），也不支持 mods、replay、成绩上传。
- 不支持 osu! 皮肤文件（.osk）直接导入；皮肤请先解压为文件夹再「导入皮肤文件夹」
  （已支持 mania 音符/长条/打击/灯光/判定线/列颜色，其余元素回退内置样式）。
- 没有音频 seek：开始播放即从音频开头播放，长前奏的谱面需要等待。
- 判定时间取“处理该帧输入事件时的音频时钟”，因此判定精度受帧率影响；
  建议开启垂直同步（默认），窗口失焦会自动暂停以免漏键。
- 谱面若在音频文件中途结束，结算会在最后一个音符 + 0.8 秒后出现。
- 渲染后端是 egui_glow，需要 **OpenGL 2.0+**。绝大多数装了显卡驱动的 Win10
  都满足；纯虚拟机（只有 Microsoft Basic Display Adapter）会启动失败，
  此时程序会弹出错误对话框并在 exe 同目录写 startup_error.txt，
  安装显卡驱动或虚拟机增强工具后即可运行。若换用动态 CRT 重新构建，见第十节。

十五、可携带（便携）包

只分发 target\release\osu4k-player.exe 一个文件就足够运行（已验证：把 exe
单独拷到带空格/中文的空目录后，导入 .osz、自动演示、暂停/继续、结算均正常，
运行后目录里只多出一个 osu4k_player.ini）。

为方便整体拷贝，可以按下面的内容自行打包（发布版提供 zip 附件，不在仓库内）：
  osu4k-player.exe      主程序（唯一必需文件）
  README.txt            本说明
  THIRD_PARTY.md        第三方组件清单
  OFL-NotoSansSC.txt    内嵌字体（Noto Sans SC）的 OFL 许可证
拷贝后双击 osu4k-player.exe 即可；不需要 assets/、src/、third_party/
或任何 DLL。谱面包仍需你自己放 .osz 文件并导入。
